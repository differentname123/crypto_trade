# 任务 (Task)

**目标**：对图文混排文章中的每张图片进行结构化降维：提取图片的客观视觉事实、结合上下文的语义价值、以及其在文章叙事中的功能定位，输出标准化 JSON 数据。

**受众**：下游图文检索、语义分析与内容理解系统。结果由机器直接解析消费，非人类阅读。

**验收标准**：
1. 图片与占位符严格按"上传顺序 ↔ 出现顺序"一一对应，映射零错位。
2. 输出为单个合法 JSON 数组，可被 `JSON.parse()` 直接反序列化；除 JSON 外无任何字符。
3. 字段结构与本提示词定义完全一致，不增删字段；枚举字段取值 100% 命中给定集合。
4. `visual_fact` 仅含画面可直接观察的信息；`semantic_core` 与 `narrative_role` 必须基于文章上下文推导；两类信息互不污染。
5. 全部字段满足各自的数量、字数与词性边界；信息不足时按规则输出空值，无任何编造。

# 背景 (Context)

**输入构成**：
1. 文章文本：位于本提示词末尾的 `<article>` 标签内，为带图片占位符（如 `[IMAGE_1]`、`[IMAGE_2]`）的完整文章。
2. 图片附件：随本次请求按先后顺序传入的纯图片，不含文件名与任何元数据。

**映射规则（唯一依据，最高优先级）**：
第 N 张传入的图片 ↔ 文章中从上到下第 N 个出现的占位符。禁止依据图片内容、主题相似度或语义相关性对映射关系进行重排、跳过或调换。

**三层信息边界**：三组字段各自回答不同问题，允许使用的信息来源不同：

| 字段层 | 回答的问题 | 允许的信息来源 |
|---|---|---|
| visual_fact | 画面中实际看到了什么 | 仅图片本身 |
| semantic_core | 这张图在本文中表达什么 | 图片 + 占位符前后段落 + 文章整体主题 |
| narrative_role | 这张图为何出现在此处、承担什么功能 | 图片 + 占位符前后段落 + 文章结构 |

# 约束 (Constraints)

## 字段规则

**image_id**
- 使用该图片对应占位符的原始标识（如 `IMAGE_1`）。若占位符本身无编号，按出现顺序命名为 `IMAGE_1`、`IMAGE_2`……

**image_type**
- 必须且只能从以下枚举中选择一个：`photo`（照片）、`chart`（图表）、`screenshot`（截图）、`meme`（梗图/表情包）、`illustration`（插画）、`diagram`（示意图）。
- 红线：禁止自创类型、近义替换或输出多值。

**visual_fact.entities**
- 字符串数组，提取画面中清晰可见的 3-6 个核心实体名词（人/物/地点）。
- 红线：只允许具体名词；禁止形容词、禁止抽象概念、禁止画面中不可见的实体。若可辨实体不足 3 个，仅输出实际可见的，不得凑数。
- 词性边界示例：✓ `["咖啡杯","笔记本电脑","办公桌"]`；✗ `["忙碌的员工","职场压力","现代生活"]`

**visual_fact.description**
- 1-2 句话，以盲人解说员视角白描"谁、在哪、在做什么、基础环境"。
- 红线：仅陈述可见事实；禁止推测身份、目的、情绪，禁止象征化解读，禁止出现"可能""似乎""暗示""象征"等词。

**visual_fact.ocr_text**
- 提取画面中视觉显著的核心文字（海报标题、梗图文案、图表结论等）。
- 红线：忽略细小背景文字、水印与无关 UI 微文案；无显著文字或无法辨认时输出 `""`；禁止编造，禁止依据上下文补全图中文字。

**semantic_core.concepts**
- 字符串数组，结合占位符前后文提取 2-4 个抽象主题/概念标签。
- 同一画面在不同语境下应产出不同概念。例：同为"打工人喝咖啡"图，前文讲加班 → `["职场压力","提神醒脑"]`；前文讲精品生活 → `["生活仪式感","精品咖啡"]`。
- 红线：必须是由上下文推导的抽象概念，禁止照搬 entities 中的具体物体名词。

**semantic_core.message**
- 一句话，20-40 个中文字符，总结"这张图在本文中真正想表达什么"。
- 红线：禁止复述画面内容（✗"一个人在办公室喝咖啡"），必须提炼其在文章中的语义价值。

**narrative_role.role**
- 必须且只能从以下枚举中选择一个：`cover`（封面）、`evidence`（事实论证）、`data_chart`（数据支撑）、`tutorial`（步骤指导）、`atmosphere`（氛围渲染）、`meme`（梗图调节）、`decorative`（装饰点缀）。

**narrative_role.logic_bridge**
- 一句话，结合前后文说明"这张图为什么出现在这里，它如何承接上文、引出下文"，须体现因果、递进、转折、例证等逻辑关系。
- 红线：禁止复制文章原句；禁止空泛表述（✗"增强文章表现力"）。

**narrative_role.style_tags**
- 字符串数组，每个标签 2-4 字，必须同时覆盖三个维度：媒介类型（如实拍/插画/3D渲染/截屏）+ 色调（如冷色调/暖色调/高饱和/低饱和/黑白）+ 质感（如胶片/极简/扁平/写实/手绘）。
- 红线：缺任一维度即不合格。

**narrative_role.emotion**
- 1-2 个描述图片情绪基调的形容词（如"专业严谨""戏谑吐槽""温馨治愈""焦虑压抑"）。
- 红线：无明显情绪倾向时固定输出 `"客观中立"`，禁止编造情绪。

## 通用红线
- 禁止编造：任何字段信息不足时输出 `""` 或 `[]`，不得以猜测填充。
- 禁止层间污染：不得把上下文推断写进 `visual_fact`（如 description 中出现"象征着…"），也不得让 `semantic_core`、`narrative_role` 沦为脱离上下文的看图说话。
- 禁止输出 JSON 之外的任何内容：包括前言、解释、推理过程、总结，以及 ```json 之类的代码块标记。

## 异常处理
- 某张图片模糊、损坏或无法解析：仍输出完整字段结构，`visual_fact.description` 填 `"图片无法解析"`，其余字段依可获取的信息填写，否则按规则留空。
- 图片数量与占位符数量不一致：按两者中较小的数量顺序配对处理，多余部分直接忽略；不报错、不中断、不为缺失的图片虚构数据。

# 输出 (Output)

只输出一个纯 JSON 数组，数组元素与图片按占位符出现顺序一一对应，对象数量等于实际成功配对的图片数量。

结构与格式示例如下（仅为格式示例，勿套用其中的内容与判断逻辑）：
