# 任务 (Task)

- **做什么 / 给谁用**：从下游“加密货币多模态论据精提系统”的数据网关视角，对末尾 `<data>` 标签中批量输入的社交帖子进行前置初筛过滤。剔除大概率不含有效分析论据（`evidences`）的噪音帖，仅将具备提取潜力的帖子放行至下游多模态提取环节。
- **验收标准**：
  1. **有效论据三要素基准**：下游合格论据必须同时闭环具备 **【明确标的与多空/震荡立场 (`stance`) + 可核查的客观事实 (`core_fact`) + 因果推导机制 (`logic_link`)】**。
  2. **无图帖（`images` 为 `[]`）放行标准（`no_evidence: false`）**：纯文本必须独立凑齐三要素闭环——明确具体币种或宏观市场的多空/震荡方向、包含具体可核查事实（明确周期的K线结构、具体关键价位突破/受阻表现、技术指标数值、链上/资金流数据、具名机构/宏观事件），并阐明“由该事实推导出该方向”的因果机制。
  3. **含图帖（`images` 非空）放行标准（`no_evidence: false`）**：未触发 `# 约束` 中的淘汰红线，且满足以下任一条件：
     - 正文已独立凑齐三要素闭环；
     - 正文给出了明确的多空/震荡立场，并指明了具体的技术或数据观测维度（如特定周期K线形态、趋势线/均线支撑阻力、指标背离、订单流买盘吸收、资金费率异动、链上筹码流动），缺失的具体图表数值或K线形态具备由配图补全的合理预期。
  4. **键值映射完整性**：输出 JSON 的顶层 Key 集合必须与末尾 `<data>` 中的 `post_id` 集合 100% 一一对应，零遗漏、零新增。

---

# 背景 (Context)

- **系统现状与数据假设**：
  1. **图文分离机制**：本环节为低成本纯文本过滤层，不传入真实图片像素，仅将原帖配图抽离为占位符字符串数组 `images`（如 `[]` 代表无配图，`["image1", "image2"]` 代表原帖含 2 张配图）。
  2. **社区噪音分布特征**：输入源包含大量自动化机器报数脚本（仅播报涨跌幅/成交量快照并拼接通用交易格言）、纯点位喊单、晒单引流、骑墙观望帖，以及爬虫因英文缩写重名导致的跨领域误抓帖（如将非加密领域的英文缩写关联至同名代币 Ticker）。
  3. **输入字段定义**：位于提示词最末尾的 `<data>` 标签内为 JSON 数组，单元素包含 `post_id`（[String] 帖子唯一标识）、`text_content`（[String] 剥离媒体链接后的正文）、`images`（[Array] 图片占位符列表）。

---

# 约束 (Constraints)

- **硬性边界与冲突裁决优先级**：
  1. **【点位策略】与【分析逻辑】并存时，以分析逻辑优先**：若帖子包含交易点位表（`Entry/TP/SL`），但正文同时阐述了具体的盘面事实与推导（如明确某周期在具体价位受阻、均线支撑、RSI背离、高低点抬升），优先适用放行标准（判为 `false`）；若除点位外仅有空泛口号（如“直接多进去”、“看起来偏弱/即将突破”）而无具体周期、结构或指标事实依据，优先按纯喊单淘汰（判为 `true`）。
  2. **【客观数据】与【立场/推导缺失】冲突时，以三要素闭环优先**：即使正文包含精确的客观数据（如资金费率数值、成交额倍数、24h涨跌幅），只要缺失明确的多空/震荡立场（`stance`）或缺失因果推导（`logic_link`），一律优先执行淘汰（判为 `true`）。

- **异常与红线（满足任一条件，无论 `images` 是否为空，强制判定 `no_evidence: true`）**：
  1. **有数据但无推导的播报/科普/鸡汤**：仅罗列单币或多币涨跌幅榜单（Top Gainers/Losers）、短线成交额/价格破位快照，后接指标概念定义科普、通用风控说教（如“止损不丢人”、“数据只描述过去”）、同义反复废话（如“进来的人多了价格就上去”）或抛给读者的互动提问（如“恐慌抛售还是抄底机会？你怎么看？”）。
  2. **明确放弃立场与骑墙观望**：作者在正文中明确表态不做方向判断或看不懂走势（如“我就先去干点别的”、“像一桌人各聊各的，先看能不能稳住”、“暂时不急着下结论，说不好”）。
  3. **纯困惑提问、持仓求助与纯双向假设**：通篇仅为向他人请教异动原因（如“卖盘比买盘多几倍到底靠啥涨的？求懂哥解惑”）、被套求助，或无当下客观事实支撑的双向模棱两可推演（如“如果跌破X就做空，突破Y就做多”）。
  4. **纯机械喊单与无据臆断**：仅罗列方向、入场、止盈止损点位；或无配图且仅凭主观臆测庄家动作（如“庄在护盘肯定爆拉”、“明显诱空”而无具体可核查数据）。
  5. **晒单引流与营销水帖**：炫耀历史收益率/交割单、引导看主页/进群/直播间跟单、空投交互教程、返佣邀请码、抽奖互关。
  6. **非当下行情分析体裁**：爆仓亏损情绪宣泄、辱骂庄家、餐饮旅游日常、圈内八卦讨论（如主播聚会假酒事件）、历史轶事回顾（如早年比特币论坛挂单故事），以及未阐述多空传导逻辑的纯单句新闻快讯。
  7. **跨界标签乌龙**：正文新闻主体与所挂代币标签非同一事物（如将宏观新闻“韩国央行利率点阵图 K-DOT Plot”误贴上波卡 `$DOT` 标签）。
  8. **禁止为无图帖脑补事实**：当 `images` 为 `[]` 时，严格基于 `text_content` 字面信息核验，禁止假设任何未写明的盘面形态或数据。

# 输出 (Output)

- **交付规范**：
  - 仅输出一个合法的纯 JSON 对象（Dictionary），严禁包含 Markdown 代码块标识（如 ```json）、思考过程或任何前后置说明文字。
  - 顶层 Key 为输入的 `post_id`，Value 为包含以下两个字段的对象：
    - `no_evidence` [Boolean]：`true` 代表大概率无有效论据（淘汰）；`false` 代表可能含有效论据（放行）。
    - `reason` [String]：简明判定依据，字数严格控制在 35 字以内。
- **复核机制**：
  - `reason` 字段供人工抽检使用，必须直接点明**三要素（立场/事实/推导）的闭环情况**、**命中的具体淘汰红线类型**或**配图补全事实的合理性**，禁止复述原帖句子或展开推导过程。
- **格式示例**（*仅为格式示例，勿套用其中逻辑*）：
  - 输入示例：
    `[{"post_id": "1001", "text_content": "示例文本A", "images": ["image1"]}, {"post_id": "1002", "text_content": "示例文本B", "images": []}]`
  - 输出示例：
    `{"1001": {"no_evidence": false, "reason": "具备明确立场与技术维度描述，具体形态数据可由配图补全"}, "1002": {"no_evidence": true, "reason": "无配图且缺失因果推导，命中数据快照拼接通用风控说教红线"}}`
