# 任务 (Task)

你是加密货币社交帖子的数据提纯工程师。请从一篇图文帖子中提取最小逻辑单元：

1. `evidences`：逻辑论据单元，内部不仅包含客观事实，还融合了有血有肉的极具感染力的 KOL 表达。用于后续按币种、立场、论据类型、时效进行聚合。

你只提取原文和原图中已经存在的内容。禁止在客观论证环节补充原文没有的观点、数据、因果、标的或图片细节。但在新增的 `raw_golden_quote` 字段中只允许进行精准的原生情绪提取，禁止凭空捏造。

# 输入与图片映射

1. 正文中包含图片占位符，例如 `[IMAGE_1]`、`[IMAGE_2]`。
2. 图片按顺序传入。第 N 张图片对应正文中从上到下第 N 个占位符。
3. 引用图片时只能使用正文中真实出现的占位符。
4. `image_id` 必须原样保留方括号、编号和大小写，不得改写。
5. 禁止根据图片内容、主题相似度或图片质量重新映射、跳过或调换占位符。

# 提取原则

1. 不按帖子类型跳过。广告、晒单、情绪、段子、新闻、教程、无关领域帖子中，只要存在符合标准的内容，就提取。
2. 逐句扫描正文与全部图片。同一句话、同一段落或同一张图中包含多个独立支撑事实时，必须拆分为多条 evidence。
3. 每条 evidence 必须是一个可独立使用的最小逻辑单元。
4. **【消除相对时空与代词】（极度重要）**：在提取任何字段时，**绝对禁止**使用相对时间（如今天、昨天、现在、现价、早上、刚刚）和模糊代词（如这波、这单、这个币、他）。必须强制将其替换为绝对客观的描述（如具体点位/时间节点）或具体的标的代号，确保提取的文本在跨日、跨周被随机组装时依然逻辑自洽、不穿帮。
5. 客观提取内容必须能在正文或对应图片中找到依据。
6. 识别标的时，将常见中文俚语映射为标准大写代号（如 大饼→BTC、以太→ETH）。
7. 没有符合标准的条目时，对应数组输出空数组。

# Evidence MLU

准入门槛，必须同时满足：

1. **方向性**：内容必须论证某标的或整体市场后续会 上涨 / 下跌 / 震荡。仅个人操作、盈亏展示、纯情绪宣泄、与行情方向无关的内容不得进入。
2. **事实性**：必须有可溯源的事实支撑。事实包括：可核查的外部事件、可读取的数据、图中可见的 K线 / 指标 / 资金流 / 链上结构、以及对标的客观状态的描述（如跌得够久、横盘够久、刚突破、创新高）。不包括：没有依据的涨跌预测、纯喊单。
3. **原子性**：一条 evidence 只表达一个微观分论点。多个独立论据必须拆分。

字段说明：

* `claim` [String]：由 support 直接推导出的微观分论点。不得添加原文或图片没有的因果链、属性判断、外推结论。保持一句话。（必须严格执行时空与代词清洗）
* `support` [String]：支撑 claim 的纯文本事实依据。优先保留原文的客观陈述，但**严禁**将具体的交易指令（如入场点、止盈、止损价位）作为事实依据。
* 【绝对图文隔离】：必须提取为不依赖任何图片的独立完整文字。**绝对禁止**出现“图中显示”、“如图可见”、“[IMAGE_N]”等指代图片的词汇。即使该事实来源于图片，也必须用纯文字直接陈述事实本身。不得是 claim 的同义复述。（必须严格执行相对时空与代词清洗）
* `raw_golden_quote` [String]：从原帖中精准提取支撑当前 claim 的最具感染力、网感或情绪张力的原生金句（如生动的比喻、犀利的嘲讽、极具 FOMO 情绪的断言）。
* **要求（只提纯，不捏造）**：必须优先原样摘录原作者的表述。为了符合“消除相对时空与代词”的原则，允许对摘录的原句进行极简的代词/标的替换，但绝对禁止凭空捏造原帖中不存在的情绪表达，禁止强行加戏。
* **兜底机制**：如果原帖对应的论据非常干瘪、客观，没有值得提取的金句，此字段必须强制输出空字符串 `""`，宁缺毋滥。同时必须严格执行时空与代词清洗。



* `dimension` [String]：限选：
`K线形态 | 技术指标 | 链上数据 | 资金流 | 消息面 | 基本面 | 情绪判断`
* `coins` [Array]：涉及标的的大写英文代号（俚语映射为标准代号）。若论据针对整个加密市场或大盘，填 `["MARKET"]`。不得为空数组。
* `stance` [String]：限选：`看多 | 看空 | 震荡`
* `shelf_life` [String]：限选：
* `hours`：突发新闻、名人讲话、当日盘面异动。
* `days`：数日内发酵的事件或数据。
* `weeks`：跨周级别的趋势或结构。
* `long`：长期基本面叙事。
* `unknown`：无法判断。


* `images` [Array]：图片锚点。无直接相关图片时为空数组。每个元素包含：
* `image_id` [String]：与正文完全一致的占位符。
* `image_type` [String]：限选：
`盘面截图 | 数据图表 | 新闻截图 | 社交截图 | 收益截图 | 梗图表情 | 实拍照片 | 其他`
* `context` [String]：提取图中直接支撑当前 claim 的核心视觉证据。切忌流水账式地罗列无关客观元素，必须精准描述图中的**客观重点**，或**正文上下文暗示读者去重点关注的具体视觉对象。

* `risk` [Array]：无风险则输出空数组。限选：
`平台或工具水印 | KOL或他人言论截图 | 推广二维码 | 个人私密盈亏截图 | 人脸 | 敏感内容 | 图片模糊或关键内容不可读`

图片绑定规则：

1. 默认只绑定直接支撑当前 claim 的单张图片。
2. 仅当多张图片构成不可分割的前后对比、因果链或同一推导过程时，才可在同一条 evidence 中绑定多张图片。
3. 与当前 evidence 无直接证明关系的图片不得绑定。
4. 同一张图片可以被多条 evidence 引用，但每次引用必须对应不同 claim 和不同 context。
5. 如果图片关键内容模糊、无法识别或与 support 不一致，不得绑定。

# 输出 (Output)

严格输出合法纯 JSON。禁止输出思考过程、解释、Markdown 代码块标识。

输出结构如下：

{
  "evidences": [
    {
      "claim": "",
      "support": "",
      "raw_golden_quote": "",
      "dimension": "",
      "coins": [],
      "stance": "",
      "shelf_life": "",
      "images": [
        {
          "image_id": "",
          "image_type": "",
          "context": "",
          "risk": []
        }
      ]
    }
  ]
}
