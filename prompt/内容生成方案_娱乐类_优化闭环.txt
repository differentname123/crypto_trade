### 一、 项目背景与核心目标

我的项目是从各大社交内容平台（如微博、小红书、贴吧、各类图文社区等）抓取海量原始图文帖子，通过大模型自动化筛选与二次轻度加工，转化为我方账号可直接发布的高质量新图文帖（多媒体仅限图片，无视频）,目前我会发布在 biance 和 欧易 平台。

抓取来的原始帖子质量参差不齐：既有硬广、无聊流水账、带强烈个人身份锁定的废帖，也藏着大量极具传播潜力的神帖（奇葩吃瓜、暴富与破产反差、人性潜规则、扎心嘴替、搞笑神图等）。

**我的核心目标只有一个：一切为了高流量，且像极了活人发的原生帖！**
不限题材、不限垂直领域，只要能筛选出具备大众爆款基因的帖子，并在不破坏原帖灵魂与节奏的前提下，顺着原帖的闪光点微调换皮，变成“我自己能自然发出的帖子”，实现极高的前 3 秒停留率、点图率、完读率与评论区互动率（点赞、转发、盖楼吵架/共鸣）。

---

### 二、 核心处理哲学（一手直连 + 顺势微调，拒绝模板化看图说话）

爆款内容的核心魅力在于其原本的“具体细节、留白悬念与神级配图”。因此，本项目彻底放弃“多帖拆碎再拼接”，同时也**彻底摒弃“一阶段把图片翻译成文字摘要、二阶段拿着二手摘要扩写小作文”的传话筒模式**，确立以下四大核心铁律：

1. **死保单帖完整性（1对1流转）**：一篇好帖子单独拎出来就是最好的爆款胚子，绝不与其他帖子强行杂交。
2. **拒绝“二手信息污染”，二阶段直面一手原图原文**：一阶段绝不对图片做看图写话式的二手转述；二阶段直接接收【原始全文 + 真实原图】，让负责写文案的大模型亲眼看图，天然明白“哪些画面读者一眼能看到、正文绝不多嘴复述”。
3. **顺势微调（看菜下饭，拒绝强套营销号模板）**：改写前先拆解原帖的“核心流量点”**和**“原本做得好的点”——
* 原帖若靠“短句戏谑 + 图片视觉反转/长图故事”**出彩（如撞切糕戏称豪车没了、拿纪念币装傻问真假），改写就顺着它走**【极简留白路线】（15~65字），绝不剧透底牌、绝不替网友百度答题；
* 原帖若靠“炸裂故事/极端盈亏数据”**出彩但废话黑话太多，改写就走**【去肥留瘦路线】（80~200字），砍掉说教铺垫，把最刺眼的数字反差拎到第一句。


4. **自然去“我”化，解决“能不能归我所用”**：剔除私人大水印、引流码以及与事实无关的纯气氛表情包；视角上**默认优先采用“无主语直抛”**（既不硬装当事人“我”导致包浆老图穿帮，也不用满屏“刚刷到一个老哥”暴露搬运号属性），让帖子自然得像冲浪活人的随手吐槽。

### 三、 核心实现流程（“批量粗筛 + 单帖多模态精改”两阶段架构）

#### 第一阶段：批量纯文本粗筛（多帖打包调用，不传图片，极低成本过滤）

大模型扮演高效的“初筛垃圾桶过滤器”，一次性接收 10~20 篇帖子的【纯文本 + 图片占位符数量（如 `[IMAGE_1]`）】，不消耗昂贵的视觉 Token，只做一件事：

1. **剔除必死废帖（`keep: false`）**：
* 直接拦截纯微商/诈骗硬广、纯粹推销冷门标的的合约代码软广、通篇只有枯燥点位参数的分析帖、无图且无反差的口水话水贴、以及强绑定名人身份无法换皮的营业帖。


2. **图文悬念一律放行（`keep: true`）**：
* 凡是文本自带反差/槽点/情绪的帖子，一律放行；
* **【悬念短帖保护机制】**：只要帖子带有 `[IMAGE_n]` 占位符且文字不是硬广——哪怕配文只有短短十几个字（如“完犊子了闯大祸了”、“这种情况怎么办”），说明核心笑点或文字长图全在图片里，**一阶段无条件放行**，交由二阶段看真图定夺！


3. **提取事件简签（`event_key`）**：
* 用 4~8 个字概括帖子所聊的核心事件（如“罗曼尼康帝假酒”、“早市5元猴币”），供中间层去重使用。



#### 衔接阶段：纯代码极简过滤去重（零复杂组装）

1. **条件捞取**：筛选 `keep == true` 且未过期的记录。
2. **一手数据 1 对 1 直传**：将该条帖子的【原始文本 + 真实图片流】直接传给第二阶段。

#### 第二阶段：单帖多模态“验货 -> 拆解优点 -> 顺势改写”（一帖一调用大模型）

大模型扮演“深谙流量的顶级野生冲浪手”，直接面对一手原文与真实配图，在**单次调用**中按顺序完成以下三步闭环：

1. **第一步：看图验货与可用性兜底（`usable` & `selected_images`）**
* **洗图**：亲眼检查图片，剔除大水印、二维码、真人自拍(名人或者公众人物的照片可以使用)，以及**与正文事实毫无关系的通用搞笑表情包**（防止对着表情包瞎编剧情），仅保留真正支撑看点的有效图片 ID。
* **兜底熔断**：看完真图并砍掉原文软广尾巴后，若发现图片糊/全是水印、或笑点需要圈外人动脑算超过 2 秒才能懂（高门槛圈层自嗨）、或剥离广告后毫无看点，直接判定 **`usable: false` 并中止生成**，后端直接丢弃不发！


2. **第二步：拆解“流量点”与“原帖做得好的点”（`viral_analysis`）**
* 在动笔前先想清楚：① 普通网友 1 秒停下来的**核心流量点**是什么？（准确识别原帖是自嘲反讽、装傻钓鱼还是真炫耀，认清圈内网名外号）；② **原帖表达上做得好的点**是什么？（是短促留白不剧透？还是故事数据够炸？）；③ 确定本次是顺着原帖做“短句留白微调”**，还是做**“砍废话去黑话的故事重塑”。


3. **第三步：顺势微调与神评生成（`post_text` & `bait_comments`）**
* **图文互补不剧透**：图里一眼能看懂的画面、长图里的文字、以及视觉反转包袱，正文绝不复述当“盲人读图说明书”；装傻求鉴定帖绝不自己百度揭晓答案。
* **去黑话与去营销号口癖**：将阻碍理解的生僻行话翻译成大白话（顺手用半句话补齐逻辑桥梁，但保留“庄家、做空、爆仓、退市”等大众懂的爽词）；全面封杀“刚刷到一个老哥 / 最绝的是 / 你们自己品品 / 这到底是A还是B”等 AI 高频套话。
* **配套一楼神评（2~3条）**：围绕图片盲点补刀、顺竿爬接梗、或逆风抬杠生成 18 字以内的碎片化真人口语评论，把正文故意留白的包袱在评论区点破，直接引爆盖楼。

# 提示词工程设计范式 (Prompt Engineering Paradigm)

### 核心心智模型

**把提示词当成写给资深工程师的“接口契约与需求单”**：已知条件写准，正向验收与负面红线正交解耦，异常降级路由写死，确定性校验移交代码，交付 Schema 说明白，然后把具体的解题路径留给模型。

---

### 标准化四段式结构

在编写提示词时，强制使用明确的标题或标签（如 Markdown/XML）将内容物理隔离，严禁跨模块重复同一条规则：

#### 1. `# 任务 (Task)`

* **做什么 / 给谁用**：明确核心目标、受众语境与视角定位。
* **正向验收标准（与约束正交解耦）**：仅定义“合格交付物的最终正向特征”（即做到什么程度算好，模型会据此进行内部生成质量自检）。**严禁**在此处混写淘汰阈值或负面禁令。

#### 2. `# 背景 (Context)`

* **喂足事实**：提供所有相关的客观数据、业务现状与唯一事实基准。
* **材料隔离与彻底尾置**：大块的文档、代码或待处理数据，必须使用专用标签（如 `<data></data>`）包裹。**所有动态输入（含动态文本块与多模态图片流）必须统一移至提示词/消息序列的最末尾**，确保前段静态指令 100% 命中 API 前缀缓存（Prefix Caching）。

#### 3. `# 约束 (Constraints)`

* **冲突优先级**：明确多个目标发生冲突时的取舍排序（如：`事实准确 > 原文留白 > 措辞修饰`）。
* **准入与硬性边界**：预算、技术限制及触发直接拒单/淘汰（如 `usable: false`）的硬性阈值。
* **异常红线与逃生舱机制（防模型破防核心）**：
1. **区分运行模式的降级路由**：**多轮对话模式**下信息不足时直接向用户提问；**单轮 API 管线模式**下信息不足时必须触发预设的降级状态码，严禁开口提问破坏输出格式。
2. **禁令必须配“逃生舱”**：严禁只写“禁止做 A”，必须采用 **“禁止 [底层语病/机制 A]，遇到该场景时直接执行 [零风险替代动作 B]”**（如：“禁止用形容词渲染情绪 → 直接陈述客观数字或留白停笔”），消除模型的改写焦虑。
3. **反枚举铁律（≤3 靶子词）**：同类风格或语体禁令必须提炼为底层机制，括号内举例**严禁超过 3 个代表词**；超过 5 个词的字面黑名单或固定符号清理，强制下沉至代码后处理层（Code Linter）。



#### 4. `# 输出 (Output)`

* **交付规范与状态互斥**：明确输出格式、篇幅上下限（含是否允许极短留白），以及不同状态码下的字段互斥填空规则（如淘汰状态下哪些字段必须置空）。
* **先验复核机制（自回归顺序强约束）**：若需模型进行逻辑自检或人工复核，要求模型输出精炼的“关键依据与边界假设”。**在结构化输出（如 JSON）中，状态判定与复核依据字段必须排列在最终生成内容字段之前**，利用自回归生成顺序，让复核字段充当后续内容生成的注意力锚点。

---

### 五大设计原则

1. **定问题，不定解法**
明确目标和边界，把具体的推理路径留给模型。**删除教导模型“请一步步思考”的过程引导指令**，用“正向验收标准 + 前置复核字段”代替过程引导。
2. **事实做加法，指令做减法，确定性归代码**
补充足量决策所需的背景和数据；**坚决删除**情绪激励（“深呼吸”）、增智型人设（“你是智商200的专家”）、跨模块重复强调，以及**任何可用代码正则表达式解决的字面黑名单与符号清洗规则**。
3. **角色仅用于定位视角**
人设不用于提升模型智商，只用于限定输出视角、语体颗粒度或受众语境（如：“以真实冲浪网友的第一现场独白视角”或“从安全审计视角审查”）。
4. **Schema 契约优先，示例严禁污染字面量**
优先通过清晰的字段规则或 API 原生 Structured Outputs 约束格式。
* 若在提示词内提供 JSON 结构模板，**严禁在合法的字符串值内混写竖线枚举（如 `"A | B | C"`）或容易被照抄的业务假数据**（枚举值应在交付规范中独立列出）。
* 若必须提供 Few-shot 示例，**必须提供完整的“输入-输出对”**，并强制声明：“*仅为格式示例，勿套用其中逻辑与内容*”，防止模型思维窄化。
